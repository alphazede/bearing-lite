# Pre-packet check

Before composing a packet, the Orchestrator checks the required packet fields:
one objective, observable acceptance, write set, existing commands, named
evidence (digests, commands, and exit codes, not narrative logs), and a time
target with "at the limit, return what you have and list the gaps". Packets
name the verified Git object for tracked inputs and keep the exact author draft
through assurance. For a review before a first live apply, require the frozen host and class rows and the
exact proposed operand list, not only the executor diff. Planning
specialist packets name only that specialist's own artifact checker; the
repository gate runs once at assembly. A missing or empty field is a compilation
gap, not a packet. In an execution packet, an empty proof-row list takes the
slice goal as acceptance, and an empty command list takes the command that
`seit.json` ties to each proof row it shares with a Test Implementer slice. For **execution packets** (after assembly, once
`implementation.json` and `seit.json` exist), the Orchestrator runs the handoff
compiler (`tools/compile-handoff.mjs`) instead of writing the packet by hand.
For **planning (pre-assembly) packets** before `implementation.json` and
`seit.json` exist, compose from the Prompt template (`../../prompt/SKILL.md`)
using the same field check.

It then runs the advisory decision-model check: is the objective one
observable outcome, and is each acceptance item observable by something other
than the author? Name the rawest source the agent should read instead of a
summary. Settle by experiment any choice an experiment can settle. Send the
uncertain band to the owner. Reuse settled planning; never re-interview.

Do not trust this advisory check until its objective and acceptance judgments
have been measured on real packets. The Prompt skill stays the composer of
the bounded handoff for the assignment the Orchestrator already selected.
