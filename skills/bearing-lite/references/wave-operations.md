# Wave operations

## One task graph

Keep one authoritative task graph for this wave and record assignment identity,
candidate, status, completed evidence, and remaining work durably; create no
second plan graph, and never redispatch completed work after interruption,
compaction, or resume.

## Method skills in packets

Name the applicable method skills in each packet and verify the selection at
receipt. Keep selected, loaded, and performed separate: a missing method skill
is a visible gap, never claimed as performed and never silently substituted
with another method. Routing never grants fan-out, independent review, or
publication authority.

## Storage handoff

Release disposable wave outputs after their consumers finish; retain integration
inputs until the Orchestrator accepts the handoff, giving each retained path an
owner, a reason, and a release event. Packets name the verified Git object for
tracked inputs and keep the exact author draft through assurance rather than
reconstructing vanished history. Do not remove another wave's files, and a
child `COMPLETE` is not permission to delete integration evidence. The
Orchestrator guarantees cleanup by running the storage `recover` command in
finally, cancellation, and restart paths (see
`storage-lifecycle.md`).

## Measured repair loop

Use this loop only when a packet opts in. Each repair or follow-up packet then
names its starting reading: the failing gate or case IDs and the open finding
IDs it must close, with the command that produced them. Size each packet to one
reviewable increment of that reading, not from narrative. The return receipt
reruns the same command and states the reading after the run with its exit
code. Record both readings in the existing task graph. Dispatch another packet
only within the remaining authority and repair allowance. The loop ends when
the named gates pass or when its repair allowance ends; an exhausted allowance
leaves the failure open. Send standing lessons through reflect-and-correct. The
loop adds no agent, review, gate, stop, memory file or cadence change, and the
existing caps still apply.
